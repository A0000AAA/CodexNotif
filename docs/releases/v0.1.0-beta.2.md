# CodexNotif v0.1.0-beta.2

这是一个公开测试版本，包含 Windows 客户端、Java 服务端和 Android 客户端。

## 本次更新

- Android 可选择一个 QQ IMAP 文件夹进行监听，未设置时使用根收件箱 `INBOX`。
- 文件夹列表同时兼容递归 `LIST`、订阅文件夹与中文 IMAP 路径。
- QQ 未向 IMAP 开放自定义文件夹时，App 会提示开启“收取我的文件夹”。
- UID 游标按账户、文件夹和 `UIDVALIDITY` 隔离，切换文件夹不会把历史邮件全部当作新邮件。
- 只有通知成功后才提交邮件 UID，临时通知失败会在下一轮重试。
- 修正 Android 系统铃声调用通道，保留用户选择的本地或系统音源。
- Android 在普通后台继续监听；用户从最近任务划掉 App 后停止监听，不自动复活或开机自启。
- Windows 客户端使用当前用户安全存储保存服务器地址和访问密钥，并兼容受限 Windows 环境。

## 推荐部署顺序

1. 部署 Java 服务端并配置访问密钥、邮件发送参数和 HTTPS 反向代理。
2. 启动 Windows 客户端，填写服务器地址和同一个访问密钥，然后安装 Codex 完成通知。
3. 在 Android 客户端填写 QQ 邮箱地址及独立授权码，配置监听文件夹、提醒规则和铃声。

三个组件必须使用同一个服务端访问密钥。不要把真实密钥写入仓库、脚本、截图或日志。

## Android 使用方法

1. 在 QQ 邮箱网页端开启 IMAP/SMTP 服务并生成独立授权码。
2. 在 App 设置页填写 QQ 邮箱地址与授权码，并点击“测试 QQ IMAP 登录”。
3. 如果邮件规则会把通知移入自定义文件夹，打开“监听文件夹”选择对应目录。
4. 如果只看到五个系统文件夹，请在 QQ 邮箱网页版的“收取选项”中开启“收取我的文件夹”，保存后重试。
5. 添加提醒规则，选择普通通知或强提醒，并选择需要的铃声。
6. 开启后台监听，确认“IMAP 最近检查”持续更新。

普通后台会继续监听；从最近任务划掉、强行停止或重启手机后不会自动恢复，需要重新打开 App。小米/HyperOS 用户如果无法真正划掉任务，请先解除最近任务卡片锁定。

## Windows 使用方法

1. 解压完整的 Windows x64 发布包，不要只复制单个 EXE。
2. 打开 `CodexNotif.exe`，在服务器设置中填写 HTTPS 地址和访问密钥。
3. 配置发信账户，并完成必要的邮箱授权流程。
4. 点击安装 Codex 通知；程序会生成适配当前安装路径的通知脚本。
5. 执行一次短 Codex 任务，等待主任务停止并确认邮件成功发送。

Codex 子 Agent 的内部完成不会单独发信；只在主任务一轮完成、等待下一次输入时发送。

## 服务端使用方法

服务端需要 Java 17。生产环境建议通过宝塔或其他反向代理提供 HTTPS：

1. 上传服务端 JAR 到独立目录。
2. 在环境变量中设置访问密钥和邮件服务配置。
3. 启动 JAR，并让反向代理转发到服务端监听端口。
4. 仅开放必要入口，启用 HTTPS，并限制管理接口访问。
5. 使用带访问密钥请求头的健康检查确认服务正常。

完整环境变量、宝塔部署和安全配置示例见仓库 `README.md`。

## 下载与校验

- `CodexNotif-Windows-x64-v0.1.0-beta.2.zip`：完整 Windows 自包含发布目录。
- `CodexNotif-Server-v0.1.0-beta.2.zip`：Java 服务端及许可证说明。
- `CodexNotif-Android-v0.1.0-beta.2.apk`：正式签名 Android 安装包。
- `SHA256SUMS.txt`：所有发布文件的 SHA-256 校验值。

下载后请先核对 `SHA256SUMS.txt`。Android APK 的 application ID 为 `org.codexnotif.mobile`，系统显示的完整版本名为 `v0.1.0-beta.2`。

## 已知限制

- 当前 iOS 目录仅保留工程骨架，不代表已达到 Android 同等功能。
- QQ 自定义文件夹是否可见由 QQ 网页端“收取我的文件夹”开关控制，App 无法绕过服务端限制。
- 闹钟类音频是否通过蓝牙播放由 Android、耳机能力和厂商策略共同决定。
- 本版本是预发布版本，建议先在测试环境中完成三端验证。
