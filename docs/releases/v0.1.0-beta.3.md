# CodexNotif v0.1.0-beta.3

这是一个公开测试版本，包含 Windows 客户端、Java 服务端和 Android 客户端。

## 本次更新

- Android 强提醒现在把短时间内到达的多封匹配邮件合并成一个会话，通知显示“收到多封匹配邮件”和累计数量。
- 同一提醒会话只保留一个通知和一个全屏页面；后续邮件原位更新，不会反复弹出多个页面或重新从头播放铃声。
- “我知道了”会同时停止铃声、关闭页面并清除当前提醒；旧会话的延迟操作不会误关新提醒。
- 强提醒事件改为串行处理，并增加会话令牌、更新失败回滚以及停止失败后的重复确认重试。
- 铃声播放移到 Android 后台服务，应用切到普通后台后仍能继续提醒；用户从最近任务划掉 App 后仍按既有低侵入策略停止监听。
- 增加小米/HyperOS 启动桥，统一后台通知、全屏提醒与冷启动路由，减少重复播放和状态不同步。

## Android 重要迁移说明

本版本轮换了 Android 发布签名，与 `v0.1.0-beta.2` 及更早版本不兼容。旧版用户必须先记录服务器、访问密钥、邮箱、IMAP 授权码、监听文件夹、提醒规则和铃声设置，然后卸载旧版，再安装本版本。卸载会清除 App 本地配置，Android 无法在保留数据的情况下跨签名覆盖安装。

从 `v0.1.0-beta.3` 开始，请保留本版本安装包和发布密钥对应的升级链；不要再安装旧签名 APK 覆盖本版本。

## 推荐部署顺序

1. 部署 Java 17 服务端，配置访问密钥、邮件发送参数和 HTTPS 反向代理。
2. 启动 Windows 客户端，填写服务器地址和同一个访问密钥，然后安装 Codex 完成通知。
3. 在 Android 客户端填写相同服务器信息、QQ 邮箱地址及独立授权码，再配置监听文件夹、提醒规则和铃声。

三个组件必须使用同一个服务端访问密钥。不要把真实密钥写入仓库、脚本、截图或日志。

## Android 使用方法

1. 如已安装 `v0.1.0-beta.2` 或更早版本，先记录配置并卸载旧版。
2. 安装 `CodexNotif-Android-v0.1.0-beta.3.apk`，打开 App 并授予通知权限。
3. 填写服务器地址和访问密钥；填写 QQ 邮箱地址与独立授权码，并测试 IMAP 登录。
4. 如果通知邮件会被规则移动，选择对应监听文件夹；未设置时使用根收件箱 `INBOX`。
5. 添加提醒规则，选择普通通知或强提醒，并选择铃声。
6. 开启后台监听，确认“IMAP 最近检查”持续更新。
7. 用“模拟 Codex 完成”验证通知、全屏页面、铃声和“我知道了”；真实邮件测试应确认多封匹配邮件只合并为一个提醒。

普通后台会继续监听；从最近任务划掉、强行停止或重启手机后不会自动恢复，需要重新打开 App。小米/HyperOS 用户如果无法真正划掉任务，请先解除最近任务卡片锁定。

## Windows 使用方法

1. 解压完整的 Windows x64 发布包，不要只复制单个 EXE。
2. 打开 `CodexNotif.exe`，填写服务器 HTTPS 地址和访问密钥。
3. 配置发信账户，并完成必要的邮箱授权流程。
4. 点击安装 Codex 通知，再执行一次短任务验证主任务停止时能够发信。

Codex 子 Agent 的内部完成不会单独发信；只在主任务一轮完成、等待下一次输入时发送。

## 服务端使用方法

服务端需要 Java 17。生产环境建议通过宝塔或其他反向代理提供 HTTPS，完整环境变量、反向代理和安全配置示例见仓库 `README.md`。

## 下载与校验

- `CodexNotif-Windows-x64-v0.1.0-beta.3.zip`：完整 Windows 自包含发布目录。
- `CodexNotif-Server-v0.1.0-beta.3.zip`：Java 服务端及许可证说明。
- `CodexNotif-Android-v0.1.0-beta.3.apk`：正式签名 Android 安装包。
- `SHA256SUMS.txt`：所有发布文件的 SHA-256 校验值。
- `LICENSE.txt`、`THIRD_PARTY_NOTICES.md`：项目和第三方许可说明。

下载后请先核对 `SHA256SUMS.txt`。Android application ID 为 `org.codexnotif.mobile`，系统显示的完整版本名为 `v0.1.0-beta.3`。

## 已知限制

- 当前 iOS 目录仅保留工程骨架，不代表已达到 Android 同等功能。
- Android 全屏提醒受系统“全屏通知”权限、勿扰模式和厂商策略影响；有通知但不全屏时，请先检查系统权限。
- 闹钟类音频是否通过蓝牙播放由 Android、耳机能力和厂商策略共同决定。
- 本版本是预发布版本，建议先在测试环境中完成三端验证。
