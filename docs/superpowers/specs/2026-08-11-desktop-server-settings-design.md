# 桌面客户端服务器设置设计

## 背景

公开版桌面客户端目前只从 `CODEXNOTIF_SERVER_URL` 环境变量读取服务器地址；
变量不存在时退回 `http://localhost:27843`。客户端界面没有配置入口，
`settings.json` 也不保存服务器地址。因此远程部署用户即使已经迁移邮箱绑定和
Device Token，前台检查与后台 Codex 完成通知仍会连接到本机地址。

## 目标

- 在桌面客户端提供可见、可保存、可测试的服务器地址设置。
- 前台服务器检查、邮箱绑定、测试通知与后台 `--codex-notify` 使用同一地址。
- 兼容没有服务器地址字段的旧版 `settings.json`。
- 保留环境变量作为无人值守部署的回退配置。
- 修改服务器地址时不得清除邮箱绑定、Device Token 或待验证状态。

## 非目标

- 不在服务器地址中保存账号、密码、Token 或证书。
- 不增加多服务器列表、自动故障转移或远程配置同步。
- 不改变移动端与服务端 API。

## 配置模型与优先级

在 `AppSettings` 增加可为空的 `ServerBaseUrl` 字段。实际地址按以下优先级解析：

1. `settings.json` 中非空的 `ServerBaseUrl`；
2. 非空的 `CODEXNOTIF_SERVER_URL` 环境变量；
3. 内置默认值 `http://localhost:27843`。

旧配置缺少该字段时，JSON 反序列化得到空值并自然进入环境变量或内置默认值，
不需要一次性迁移脚本。

服务器地址必须是绝对 `http://` 或 `https://` URI，必须包含主机，且不得包含
用户名、密码、查询字符串或片段。允许反向代理使用路径前缀。保存前去除首尾
空白和末尾 `/`。

## 组件设计

### ServerAddressResolver

新增无状态的地址解析器，负责：

- 验证并规范化用户输入；
- 按保存值、环境变量、内置默认值的优先级返回实际地址；
- 返回配置来源，供界面说明当前地址来自“客户端设置”“环境变量”或“默认值”。

解析器不读取邮箱或 Token，也不执行网络请求。

### RelayApiClient

`RelayApiClient` 改为在构造时接收已经解析的服务器地址，并将其作为只读
`ServerBaseUrl`。所有 `/health`、绑定和事件接口继续在该地址后追加现有路径。
客户端不再在每次请求时自行读取环境变量，避免前台与后台得到不同结果。

### MainWindow

在现有服务器状态附近增加“服务器设置”卡片：

- 服务器地址输入框；
- “保存并测试”按钮；
- “恢复默认”按钮；
- 当前实际地址、配置来源和连接结果。

窗口启动时先加载 `AppSettings`，再通过解析器创建 `RelayApiClient`。用户点击
“保存并测试”时，先验证格式；格式无效则不写文件。格式有效时仅更新
`ServerBaseUrl`，保存完整设置对象，替换当前 API 客户端并执行 `/health` 检查。
网络检查失败时保留已保存的地址和现有绑定信息，以便用户修正网络或地址后重试。

“恢复默认”清空 `AppSettings.ServerBaseUrl`，随后按环境变量或内置默认值重建
API 客户端并立即检查连接。

### 后台通知入口

`App.RunNotifyAsync` 与 Stop Hook 入口先加载同一份 `AppSettings`，再用
`ServerAddressResolver` 创建 `RelayApiClient`。这样关闭主窗口后由 Codex 启动的
后台进程仍使用客户端已保存的服务器地址。

## 错误处理与隐私

- 格式错误显示中文原因，不保存无效值。
- DNS、超时、TLS 和 HTTP 错误沿用现有状态区显示；日志只记录异常类型，
  不记录 Device Token、邮箱或通知正文。
- 输入框显示服务器地址，但不接受带用户信息或查询参数的 URI，避免误把凭据
  保存进公开可见的配置项。
- 更改地址不自动重新绑定邮箱；原 Device Token 是否被新服务器接受由测试通知
  结果决定。

## 测试

桌面端自测试新增以下回归覆盖：

- 保存地址优先于环境变量；
- 保存值为空时使用环境变量；
- 两者为空时使用 `http://localhost:27843`；
- 去除首尾空白和末尾 `/`；
- 拒绝相对地址、非 HTTP(S)、空主机、用户信息、查询字符串和片段；
- 旧版设置 JSON 缺少 `ServerBaseUrl` 时仍可读取；
- 设置保存后邮箱绑定、Device Token 和待验证字段保持不变；
- 前台与后台使用相同解析结果。

完成后运行桌面端全部自测试、Release 构建、公开仓库工作区与 Git 历史审计。

## 发布与迁移

重新发布 `CodexNotif.exe` 后，现有 `%LOCALAPPDATA%\CodexNotif\settings.json`
会由新版本原地读取。用户首次打开新版本，在“服务器设置”中填写自己的
服务地址并点击“保存并测试”；成功后重启 Codex，使后续完成事件使用新地址。
